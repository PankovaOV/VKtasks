1\. Развернуть односвязный список



На каждом шаге используются три указателя:



prev — предыдущий узел (изначально NULL)



curr — текущий узел



next — следующий узел (чтобы не потерять связь)



Порядок действий:



1\. next = cur->next — сохраняем ссылку на следующий узел



2\. cur->next = prev — разворачиваем ссылку текущего узла назад



3\. prev = cur — сдвигаем prev вперёд



4\. cur = next — сдвигаем curr вперёд



Когда cur становится NULL, prev указывает на новую голову списка (последний элемент)



Почему алгоритм работает за O(n):



Мы проходим по каждому узлу списка ровно один раз, от начала до конца. Количество операций линейно зависит от длины списка.



2\. Найти середину списка



Имеются два указателя:



\- slow двигается на 1 шаг



\- fast двигается на 2 шага



Когда fast доходит до конца списка, slow оказывается ровно в середине, потому что он прошёл в два раза меньше узлов.







3\. Удалить элемент из односвязного списка



1\. Удаление головы списка



&#x20;  Если значение головы равно data, то новая голова — это head->next. Старую голову освобождаем через free



2\. Удаление внутреннего элемента



&#x20;  Идём по списку с двумя указателями: prev и curr.  



&#x20;  Когда находим нужный узел:



&#x20;  - перекидываем ссылку и освобождаем память



Новый список не создаётся — меняются только существующие ссылки.







4\. Является ли одна строка исходной для другой



Используются два указателя:











i — по строке a (исходной)







j — по строке b



Идём по строке b. Каждый раз, когда символы совпадают, двигаем указатель i.  



Указатель j двигается всегда. Если в конце i дошёл до конца строки a, значит все символы исходной строки встретились в том же порядке внутри b.  







5\. Метод двух указателей (поиск пары)



Почему подход работает за O(n):



Массив отсортирован, поэтому можно использовать два указателя с концов: left — с начала, right — с конца



На каждом шаге считаем сумму, каждый элемент рассматривается максимум один раз, т.к. на каждом шагу мы двигаемся дальше, либо правее от начала, либо левее от конца, причем эти отрезки не пересекаются.  Поэтому время работы — O(n).







6\. Является ли слово палиндромом?



Два указателя:



left — с начала строки



&#x20;right — с конца строки



Пока left < right:



\- сравниваем символы без учёта регистра



\- если не совпали — сразу возвращаем false



\- двигаем оба указателя навстречу друг другу



Алгоритм проходит по строке один раз, поэтому работает за O(n).







7\. Метод двух указателей (удаление дубликатов)



Используются два указателя:



\- slow — указывает на позицию последнего уникального элемента



\- fast — пробегает весь массив



Когда nums\[fast] отличается от nums\[slow], значит нашли уникальный:



\- увеличиваем slow



\- записываем nums\[fast] в позицию nums\[slow]



Таким образом дубликаты перезаписываются поверх старых значений.  



Новый массив не создаётся — всё происходит in-place.







8\. Слияние двух отсортированных списков



Используется фиктивный узел dummy и указатель tail.



На каждом шаге выбирается меньший из двух текущих узлов и присоединяется к результату через изменение ссылки.



Каждый узел обоих списков обрабатывается ровно один раз, поэтому время O(n + m).



Новые узлы не создаются — меняются только существующие ссылки между узлами.  



Поэтому дополнительная память — O(1).
